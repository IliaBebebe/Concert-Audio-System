# План: поиск и импорт музыки из интернета

Статус: одобрено пользователем, реализация в работе. Дата: 30 октября 2026.

Дополнение: поиск во время воспроизведения, кнопки «В очередь» и «Запустить». «Запустить» автоматически включает готовый трек после подготовки, удерживая текущий звук до старта нового.
Ветка приложения: `codex/online-music`, создана от `codex/release-1.3` на `c855b0a` (версия исходников 1.3.4).
Предлагаемая версия выпуска: **1.4.0**; перед выпуском проверить, свободен ли тег.

## Предлагаемый сценарий

1. Рядом с поиском в деке доступен режим «В интернете». Обычный фильтр локальных треков сохраняется.
2. Пользователь вводит название/исполнителя и нажимает Enter или вставляет ссылку YouTube / YouTube Music.
3. CAS показывает до 10 результатов: название, канал/исполнитель, длительность и источник. Канал не выдаётся за подтверждённого исполнителя.
4. Действие «Подготовить в A/B» фиксирует целевую деку и очередь на момент нажатия. Видны стадии загрузки и обработки, отмена и понятная ошибка при недоступности источника.
5. Только после полной загрузки и проверки аудио трек попадает в очередь. Запуск отдельным действием; уже играющая музыка продолжается.
6. Подготовленные файлы хранятся в библиотеке CAS и воспроизводятся без интернета, с перемоткой, осциллограммой, переходами и обычной громкостью.

Первый выпуск: поиск YouTube, ссылки YouTube / YouTube Music, одиночные треки, очередь подготовки и локальная библиотека импортов. Отдельный поиск каталога YouTube Music, массовый импорт плейлистов, аккаунты и прямое потоковое воспроизведение отложены.

## Источник и ограничения

- Рекомендуемый технический вариант: отдельный процесс **yt-dlp + FFmpeg/ffprobe + поддерживаемый JS runtime (предпочтительно Deno)**. Для полноценной работы YouTube сейчас нужны также компоненты yt-dlp-ejs; проверить их наличие в выбранном дистрибутиве.
- Сначала проверить реальным прототипом поиск, загрузку и воспроизведение на доступной сети. Работоспособность нельзя гарантировать по одному наличию утилит: возможны ограничения региона, входа и антибот-проверки.
- yt-dlp умеет поиск YouTube и YouTube Music, но публичные источники могут меняться. Отдельный адаптер позволит обновлять интеграцию без переписывания плеера.
- Это не официальная интеграция YouTube Music. Официальный YouTube API/плеер не подходит для скачивания отдельного аудио, офлайн-библиотеки и привычного микширования CAS: такие действия ограничены политиками платформы.
- Доступность видео не означает разрешение на скачивание или публичное исполнение. Импорт допустим для материалов, использование которых разрешено правообладателем и правилами источника. Не заявлять, что yt-dlp снимает эти ограничения.
- Если нужен исключительно официальный способ доступа к YouTube, альтернативный объём работ — поиск через Data API и видимый встроенный плеер, с соблюдением его требований. Это другой режим с ограничениями для концертного микшера.
- Проверить лицензии конкретных распространяемых бинарников: лицензия исходников yt-dlp не равна лицензии всех standalone-сборок; FFmpeg также зависит от конфигурации. Включить обязательные уведомления и сведения об исходниках.

## Этапы реализации после одобрения

### 1. Проверка интеграции и зависимостей

- Закрепить версии утилит, источники загрузки и контрольные суммы. Не требовать от пользователя ручной установки Python, Node или FFmpeg.
- Для первого выпуска поставлять проверенные инструменты в ресурсах приложения; изменение их версии проходит отдельную проверку и выпуск CAS. Не загружать исполняемые обновления без проверки.
- Windows x64 и Linux x64 получают соответствующие бинарники. Universal macOS должен включать совместимые варианты для Intel и Apple Silicon; проверить запуск обоих наборов.
- Определить итоговый размер пакетов и работоспособность вложенных исполняемых файлов, включая разрешения и подпись на macOS.
- Проверить разрешённый для тестирования ролик: поиск → метаданные → файл → воспроизведение. Если источник требует входа/недоступен, показать ошибку; не добавлять автоматическое извлечение браузерных cookies.

### 2. Сервис импорта и файловая граница

- Новый модуль, например `online-music.js`, выполняется в main-процессе; `main.js` управляет жизненным циклом задач и IPC, `preload.js` предоставляет узкий API поиска, подготовки, отмены и прогресса.
- Запускать утилиты через `spawn` с массивом аргументов, без shell. Проверять запросы, идентификаторы, домены и отправителя IPC; renderer не задаёт команды или выходные пути.
- Игнорировать внешние пользовательские конфигурации утилит. Запретить произвольные URL и доступ к локальным/внутренним адресам, ограничить длительность, объём, число результатов и время задач.
- Хранилище импортов: отдельный управляемый каталог в `userData`, индекс с ID источника, названием, ссылкой и локальным файлом. Временные файлы отдельно; готовность отмечается после проверки и атомарного завершения.
- Расширить существующую файловую границу только на управляемые готовые аудиофайлы. Сохранить проверки realpath/symlink, отправителя и типа файла для чтения, метаданных и осциллограммы.
- Сохранять исходный аудиоформат, если он воспроизводится установленным Electron; иначе конвертировать в проверенный формат. Не обещать повышение качества перекодированием.
- Дедупликация по ID источника, последовательная очередь загрузки, отмена с завершением дочерних процессов, очистка незавершённых файлов и обработка нехватки диска.
- Готовые файлы остаются после перезапуска. Показывать занятое место; удаление только явное, с защитой играющих файлов и понятной обработкой ссылок из очередей.

### 3. Интерфейс и очереди дек

- Использовать существующее оформление, без смены дизайн-системы. Поиск по Enter, без сетевого запроса на каждую букву; старый ответ не заменяет результаты нового запроса.
- Результаты и задачи подготовки доступны с клавиатуры; состояние загрузки/ошибки сообщается доступным способом. Проверить основной и отделённый блок.
- Смешанные очереди содержат локальные и импортированные треки. Точное место добавления и поведение при замене плейлиста определяются захваченной целью; устаревшая задача сохраняет файл в библиотеке, не меняя новый плейлист.
- Переработать сохранение/восстановление: сейчас очередь восстанавливается перечитыванием одной папки, а это не вернёт импортированный трек из другой библиотеки. Хранить различие локальных путей и ID импортов, порядок и выбранный трек; мигрировать старое состояние без автозапуска.
- Библиотека импортов доступна независимо от выбранной музыкальной папки. Загрузка нового трека не сбрасывает играющую деку, громкость, кроссфейд и горячие клавиши.

### 4. Проверки

- Автотесты поиска/импорта с подставным адаптером: неверные входы, инъекции аргументов, отмена, таймаут, повторный импорт, частичный файл, ошибка FFmpeg, нехватка места, запрет выхода из хранилища.
- Регрессионные проверки смешанных очередей: переключение деки во время загрузки, замена плейлиста, сохранение порядка и восстановление старого/нового состояния.
- Запустить существующий `npm test`, проверки синтаксиса и `npm run build-win`.
- Проверить реальную интеграцию отдельно от детерминированных тестов: поиск по названию, обычная и Music-ссылка, проигрывание после отключения сети, отказ источника.
- Через изолированный Electron-профиль проверить обе деки, переходы, пэды, громкость, горячие клавиши, осциллограмму, перезапуск, клавиатурный фокус и адаптацию размеров окна. Пользовательскую библиотеку не менять.
- Нативные сборки CI на Windows/macOS/Linux; запуск импортёра в упакованном приложении. Сборка пакета сама по себе не подтверждает реальное сетевое воспроизведение на каждой ОС.

## Критерий готовности

Пользователь находит трек, готовит его в выбранную деку, использует вместе с локальными файлами, перезапускает CAS и продолжает работу без сети. Подготовка и ошибки источника не прерывают текущий звук. Все четыре релизных файла опубликованы под одной версией, лендинг отражает фактическую функциональность и ведёт на рабочие загрузки.
