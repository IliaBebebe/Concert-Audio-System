# Проверка CAS 1.7.1

Локальная проверка выполнена 10 ноября 2026 года на Windows x64, Node.js 22.23.2.
Основа — опубликованный CAS 1.7.0 и документация релизной ветки `53f46d6`.

## Изменения и проверки

- Воспроизведены обе ошибки: SVG поиска имел `position: static` и находился над
  полем; метка старта имела нулевые размеры из-за скрытой колонки исполнителя.
- SVG поиска учитывается правилами позиционирования. Метка старта перенесена
  в отдельный элемент рядом с названием; длинный текст сокращается, метка остаётся.
- Обновление данных файла применяется ко всем повторениям в обеих деках, включая
  скрытые поиском строки. Сброс ручного номера возвращает порядковый номер.
- Загрузочный экран закрывает рабочее пространство до восстановления очередей,
  длительностей и метаданных, осциллограммы, шрифтов и двух кадров раскладки.
  При ошибке подготовки доступен повторный запуск; учтено уменьшение анимации.
- На macOS отключены нативные traffic lights, накладывавшиеся на собственные
  кнопки интерфейса. Конфигурация окна и IPC проверяется для всех трёх платформ.
- `npm ci` без обновления зависимостей; Electron 43.8.4 установлен из закреплённого
  пакета. `npm test`: 126/126, включая повторения, сброс номера, успешную и неудачную
  подготовку и конфигурацию нативного окна Windows/macOS/Linux.
- `prepare:online` и `check:online` прошли с существующим проверенным Windows-кэшем
  того же манифеста. Проверен запуск yt-dlp, Deno и FFmpeg.
- `build-win`, проверки packaged-online и packaged-ui, `build:win` прошли. Проверены
  20 файлов UI внутри app.asar и версия 1.7.1. Начальная загрузка Electron сборщиком
  прервалась на TLS; повторная сборка использовала локальный кэш той же версии.
- Windows NSIS проверен `Get-AuthenticodeSignature`: `NotSigned`.
- YAML workflow разобран через js-yaml: Windows/macOS/Linux на нативных runner,
  четыре формата пакетов, создание draft только после успешных сборок.
- `git diff --check` и `node --check renderer.js` прошли.

## Интерфейс и сохранение данных

Использованы искусственные WAV и отдельный профиль; установленная CAS и музыка
пользователя не изменялись. Проверка через agent-browser и CDP в настоящем Electron.

- Загрузка папки и обеих дек, независимый поиск, длинное название, скрытая колонка
  исполнителя. При 1400×900 и 1000×700 нет горизонтального переполнения; значки
  находятся внутри обоих полей, метки имеют ненулевые размеры.
- Редактирование старта через форму: метка меняется сразу; Howler начинает
  воспроизведение с 7,5 с (наблюдаемая позиция после запуска — 7,94 с).
- Редактирование и сброс общего файла обновляют все три вхождения в двух деках;
  сброс убирает метки и возвращает номера 1/2/3/4 по очереди.
- Перенос Alt+→ после очистки поиска, видимая рамка фокуса с клавиатуры,
  запуск назначенного пэда клавишей 1 и остановка Esc.
- После закрытия исходного экземпляра запущено упакованное приложение с тем же
  тестовым профилем. Обе очереди с повторениями, названия, старты 7,5 с, назначение
  пэда и громкость 42%/36% восстановились; музыка автоматически не стартовала.
- В наблюдаемых сценариях нет ошибок JavaScript или unhandled rejection.
- `node scripts/smoke-packaged.js --source` и проверка готового Windows-приложения
  прошли: загрузочный экран, полная готовность метаданных и длительностей обеих дек,
  пути с кириллицей, `#` и `%`, фактический запуск Howler с 3,5 с, пэд и повторный
  запуск без автоматического воспроизведения. Эта же проверка включена в нативный
  CI всех ОС; Linux запускает GUI через Xvfb, macOS дополнительно проверяет обе
  архитектуры universal через lipo, Debian — `amd64` в пакете.

## Ограничения

Прослушивание на концертном оборудовании, физические телефоны и ручные проверки
GUI/аудио macOS/Linux не выполнялись. Их нативные сборки проверяются CI; сведения
о публикации добавляются после завершения CI и проверки всех четырёх загрузок.
