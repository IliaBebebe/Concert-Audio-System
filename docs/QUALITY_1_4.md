# Проверка CAS 1.4.0

Дата: 30 октября 2026. Рабочая ветка приложения и лендинга: `codex/online-music`.

## Локальная проверка

- `npm test`: 63 успешные проверки, включая поиск/валидацию входов, отмену и таймаут реальных дочерних процессов, очистку незавершённых файлов, дедупликацию, файловую границу, фиксацию целевой деки, смешанные очереди и восстановление без автозапуска.
- Отдельно проверена передача звука с выключенным кроссфейдом: исходящий плеер не затухает до `onplay` входящего, входящий начинает с заданной громкостью.
- Синтаксис JavaScript и разбор обоих workflow YAML успешны; версии package/lock/UI согласованы.
- Реальный поиск YouTube по названию и ссылке, загрузка аудио тестового ролика Blender `aqz-KE-bpKQ`, подготовка локального M4A и повторное получение из библиотеки без обращения к источнику.
- В изолированном Electron-профиле: поиск и подготовка во время проигрывания локального WAV, выбор целевой деки B, запуск сохранённого трека, фактическое состояние `playing=true`, громкость 0.7. Очереди после перезагрузки страницы восстанавливаются без автозапуска.
- `npm run build-win` успешно создаёт распакованную Windows x64 сборку. `scripts/check-packaged-online.js` подтверждает наличие и запуск включённых yt-dlp/Deno/FFmpeg. Наличие новых модулей и лицензий внутри app.asar проверено отдельно.
- Запущена упакованная Windows-сборка в отдельном профиле: версия 1.4.0, библиотека импортов и реальный поиск YouTube (10 результатов) работают через упакованный preload/main.
- В отдельном репозитории лендинга: шесть тестов загрузок, синтаксис release.js/interactions.js и `git diff --check` успешны. Проверены страницы шириной 390 и 1440 пикселей, добавлены описание, FAQ, сведения о конфиденциальности и лицензиях, реальный скриншот CAS.

## Границы проверки

Проверки CDP подтверждают состояние плеера и локальный путь аудио; качество звучания и задержка на концертном оборудовании не измерялись. Источник может изменять доступность по региону и антибот-ограничениям.

Нативные сборки и проверка инструментов для Windows/macOS/Linux выполняются релизным CI. Стабильный релиз публикуется только после успешных трёх jobs и наличия четырёх файлов. Статус фактического выполнения и публикации следует проверять в GitHub Actions и на странице релиза, а не выводить из локального Windows-билда.
